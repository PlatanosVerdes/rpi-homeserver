# 2026-08-31 - aceserve/jellyfin log retention + engine log noise

## What changed (streamhalla, rpi-homeserver/compose-media.yml)
1. Logging retention: jellyfin & aceserve json-file driver
   10m x 2 (20MB)  ->  50m x 5 (250MB).
2. aceserve engine config: mounted config/aceserve/acestream.conf over
   /acestream/acestream.conf (:ro). vs image default only: removed
   '--log-debug 355' and set '--log-modules root:W' (was root:D).
   Kills the periodic_check / netmon / dllock DEBUG flood (was tens of
   lines every 5-10s; 0 in steady state).
3. aceserve command overridden to pipe the engine stdout through
   config/aceserve/log-filter.awk (mounted :ro). The awk drops all
   'acestream.AttestationManager' lines (licensing/attest failures:
   'verification failed' and 'endpoint failed ...') and any traceback that
   follows one, up to the next timestamped log line. Unrelated tracebacks
   are kept. The engine args are unchanged from the image CMD.

## Why
- The DEBUG flood filled the 20MB docker log in ~1 day, so a past failure
  (Thu 2026-08-27) had already rotated away. Now: 250MB retained, only
  Warning/Error events, and the chronic attestation error hidden.

## Trade-off / notes
- The command override makes 'sh' PID 1, so 'docker stop aceserve' gives
  the engine ~10s before SIGKILL (acceptable, cache lives in /dev/shm).
- Pre-existing, NOT caused here: acestream attestation/licensing fails on
  this box (now hidden), and IPv6 netmon probes fail (no IPv6). Neither
  blocks streaming in steady state.
